# Design: v2.9.4 Clear-State and Category-Tab Fixes

**Date**: 2026-09-26
**Status**: Approved, pending implementation
**Branch**: `feature/api-v2-batch-pricing`

## Problem

The post-fill `clear` bubble mode is reset on hash-route changes but not when the user
switches Add Items category tabs while the URL remains `#/add`. The Clear action also
clears only quantity controls and leaves price/value fields filled.

## Required behavior

- Detect a change in the currently visible Add Items category and reset `bubbleMode` to
  `fill` before rendering. Price edits and quantity edits within the same category must
  not reset the mode.
- The category signature must be derived from loaded Add rows (item IDs), not from
  prices, quantities, or network state.
- Switching back to a previously visited category must show `Fill` again; the clear
  state is session-local and never persisted.
- The Clear action clears both quantity controls and price/value inputs for every
  currently loaded row. It dispatches the same input/keyup events as the existing
  per-item clear path, leaves hidden/unloaded rows alone, and resets the bubble to Fill.
- The clear summary should report cleared rows and cleared fields accurately.

- The settings header info action opens the changelog above the still-open settings panel.
- Closing the changelog by its close button, Escape, or scrim removes only the changelog
  overlay; the settings panel remains mounted and usable.
- The changelog overlay is the top dialog and retains its own focus trap and close
  behavior. The settings overlay must not receive the changelog close event.

## Non-goals

No change to API v2 batching, cache, 600 ms spacing, v1 fallback, pricing, quantity
calculation, version 2.9.4, changelog gate persistence, or the base/Personalize route
rules.

## Tests

- category A fill -> clear -> category B renders Fill;
- info action from Settings leaves Settings mounted;
- changelog close button/Escape/scrim removes only the changelog overlay and Settings
  remains present and usable;
- API v2 queue, cache, and version remain unchanged.

Add regression tests for:

- category A fill -> clear -> category B renders Fill;
- returning to category A renders Fill;
- same-category price/quantity mutations do not reset Clear;
- Clear empties numeric quantity inputs and price inputs;
- Clear unchecks quantity checkboxes and empties price inputs;
- hidden/unloaded category rows are not cleared;
- clear events and summary count are correct.
