# Design: v2.9.4 Bubble Follow-up

**Date**: 2026-09-26
**Status**: Approved, pending implementation
**Branch**: `feature/api-v2-batch-pricing`

## Objective

Apply the screenshot-driven v2.9.4 UI corrections: remove unsupported-route UI, gate
the changelog to the first Add Items visit after update, replace the Add bubble icon
with a `Fill` label, add a clear-all-quantities post-fill action, make the settings
header info action open the changelog, and remove unused Material icon assets.

## Supported routes

Only `#/add` and `#/manage` show the bubble. The base/unsupported route, Personalize,
and any unknown route hide it. The base route must not show an info icon or open the
changelog through a bubble tap. `onBubbleTap` must never fall through to a batch action
for an unsupported route.

## Changelog gate

Use a GM storage key named `changelogSeenVersion`.

- On startup or route change to `#/add`, if the stored value differs from the current
  `VERSION`, show the changelog once.
- Mark the current version as seen when the changelog closes by button, Escape, or
  scrim.
- Do not show the modal again for that version, including after reloads.
- If the API-key prompt is open on first launch, close/dismiss the key prompt first and
  then run the changelog gate; never stack the two overlays.
- The existing static `CHANGELOG` array remains the single source of displayed notes.

## Bubble states

The Add route has two user-facing states:

- `fill`: accent circle containing the text `Fill`; tapping runs Quick Fill.
- `clear`: accent circle containing the Material `close` icon; tapping clears all
  currently loaded quantity boxes, then returns to `fill`.

After Quick Fill completes, set the Add bubble state to `clear` regardless of individual
item failures. The bubble background remains the standard accent color; remove the pink
filled state and its check-circle rendering.

`clearAllQuantities()` must operate only on `getVisibleItems()`:

- for a quantity checkbox row, uncheck it when checked;
- for a quantity input row, clear the value and dispatch the same input/keyup events used
  by the existing per-item clear behavior;
- leave price inputs untouched;
- show a summary toast with the number of cleared rows;
- reset the bubble to `fill` after completion.

The Manage route keeps its refresh icon and Update All action.

## Drag and settings affordance

- The bubble drag threshold remains 6 px and long press remains 350 ms.
- While actively dragging, render the Material `settings` icon instead of the `Fill`
  text; restore the route state on pointer release/cancel.
- The settings modal header gear badge becomes a Material `info` action with
  `role="button"`, `tabindex="0"`, and an accessible label. Activating it closes the
  settings modal and opens the changelog.
- The existing long-press gesture continues to open Settings from the bubble.

## Icon cleanup

- Remove `inventory_2` from the inline icon map and delete `inventory_2.svg`; the Clear
  cache button becomes text-only.
- Remove `more_vert` from the inline map and delete `more_vert.svg` if it has no other
  consumer.
- Keep `add` for per-item buttons, `check_circle` for success toasts, `close` for the
  post-fill state/dialogs, `info` for the settings action, `settings` for the drag hint,
  and all other icons that still have active consumers.
- Update the Material asset README to list only retained assets and provenance.

## Testing

Add or update tests for:

- unsupported/base route hidden and no batch action;
- Add/Manage route actions;
- first-Add changelog display, close persistence, and no repeat after reload;
- API-key prompt closing before changelog display;
- `Fill` label and drag-to-settings rendering;
- clear-all-quantities behavior for inputs and checkboxes, price preservation, and
  bubble reset;
- post-fill close icon and accent background;
- no `inventory_2`/`more_vert` map entries or source files;
- existing API v2, PDA initialization, icon sizing, and accessibility tests remaining
  green.

## Release constraints

Keep version 2.9.4, the verified API v2 queue/cache/600 ms spacing/v1 fallback, and
all pricing/quantity behavior unchanged. Do not publish, tag, or push from this
follow-up without a final live desktop/PDA smoke test.
