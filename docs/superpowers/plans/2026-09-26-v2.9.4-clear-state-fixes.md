# v2.9.4 Clear-State and Settings Overlay Fix Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** Reset the post-fill bubble to Fill when the user changes Add Items category, make Clear empty both quantity and price fields, and keep Settings open when the changelog opened from its info action is dismissed.

**Architecture:** Add a session-local visible-category signature derived from loaded item IDs; reset the bubble mode only when that signature changes. Extend the clear-all path to use the existing per-item clear behavior for prices and quantities. Allow the settings and changelog overlays to stack, with the changelog as the top dialog and independent close behavior.

**Tech Stack:** Single-file userscript, jsdom/Vitest, GM storage, existing overlay/bubble helpers.

**Spec:** `docs/superpowers/specs/2026-09-26-v2.9.4-clear-state-fixes-design.md`

## Global Constraints

- Keep version 2.9.4 and preserve API v2 batch size 10, cache, 600 ms spacing, v1 fallback, pricing, quantity calculation, and PDA initialization.
- Only loaded Add Items rows may be cleared; never auto-scroll.
- Category signature uses item IDs only, never price/quantity values or network state.
- Clear resets bubble to Fill and clears both price and quantity controls on loaded rows.
- Settings info action opens changelog above Settings; changelog close removes only the changelog overlay.
- Do not change route support, changelog persistence gate, drag/long-press thresholds, or icon map.

## Review Focus

- Switching Add categories while hash stays `#/add` must reset Clear to Fill; price/quantity edits within one category must not.
- Clear must empty price and quantity fields but leave hidden/unloaded categories untouched.
- Changelog close via button/Escape/scrim must leave the settings overlay mounted and usable.
- No API request or cache change may result from category detection or clearing.
