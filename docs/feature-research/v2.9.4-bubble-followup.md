## Desired behavior from user

1. Base `bazaar.php#/` is unsupported; hide the bubble there and on Personalize. Add and Manage remain the only supported routes.
2. Put the full v2.9.4 change notes first in the changelog. Show the changelog automatically on the first Add Items visit after upgrading. Once dismissed, never show it again for that version.
3. Replace the Add bubble icon with the text `Fill`. During a drag, show a settings/info affordance; the requested follow-up changes the settings modal header gear to an info action that opens the changelog.
4. After Quick Fill completes, the Add bubble stays accent-colored and shows the close icon. Tapping it clears all currently loaded quantity boxes and returns the bubble to `Fill`.
5. Remove redundant icon assets and map entries that have no active consumer.

## Follow-up bug findings

- Add Items category tabs change the visible row set without changing the `#/add` hash, so the existing `hashchange` reset cannot clear the post-fill bubble mode. The reset must observe a signature derived from loaded item IDs.
- The current clear-all helper clears quantity controls only. The user confirmed Clear should also empty price/value fields.
- The settings info action currently removes the Settings overlay before opening the changelog. The user requires Settings to remain mounted beneath the changelog; closing the changelog must remove only the top overlay.

## Implementation constraints

- Do not change API v2 batching, cache, spacing, v1 fallback, quantity parsing, pricing, or version metadata.
- Only currently loaded Add Items rows can be cleared; do not auto-scroll.
- Detect category changes from item IDs only, so price and quantity edits within the same category do not reset the bubble mode.
- Persist changelog dismissal per version in GM storage.
- The settings and changelog overlays may stack when opened from the settings info action, but the changelog must be the top dialog and close independently.
- Keep the changelog content static and local; no external data or HTML injection.

## Design decision: base `bazaar.php#/` is not a supported bubble route

`getBubbleRoute()` was changed to return only `add` or `manage`; every other hash —
the base `bazaar.php#/`, `personalize`, and any unknown route — returns `unsupported`.

Reasons:

- The base route has no batch action, so the old `main` state could only open the
  changelog, and the old `personalize` state hid the bubble while still rendering an
  icon during a drag.
- The once-per-version changelog gate is keyed to the Add route. If the changelog could
  be seen from a route where the bubble is hidden, the version would be marked seen
  before the user ever saw the notes next to the bubble.
- The drag-hint render branch runs before the state-specific branches, so it must not
  un-hide the bubble; the route check therefore has to precede it.

## Shipped implementation (v2.9.4)

- `torn-bazaar-quick-pricer.user.js`: `getBubbleRoute()` returns `unsupported` for every
  non-Add/Manage hash; `renderBubbleContent()` hides the bubble on `unsupported` and
  then renders the drag `settings` hint, the Manage `refresh` icon, the Add `close`
  clear state, or the text `Fill` label (`.qp-bubble-label`), each with a per-state
  `aria-label` from `BUBBLE_LABELS`. The dead `.qp-bubble-filled` and `.qp-btn svg` CSS
  rules were removed with the `check_circle` completion state.
- `clearAllQuantities()` clears the quantity of every row in `getVisibleItems()` —
  unchecking quantity checkboxes and blanking plain quantity inputs with `input` and
  `keyup` events — then returns the bubble to `fill` and toasts the count. It only runs
  from the bubble, needs no API key, and never scrolls.
- `bubbleMode` (`fill` / `clear`) is in-memory only; it is set to `clear` after a batch
  settles and reset to `fill` on `hashchange` and after a clear.
- `maybeShowChangelog()` returns early unless the route is `add`, skips while another
  script overlay is up, and is called from the API-key prompt's close paths so the two
  modals never stack. `CHANGELOG_SEEN_KEY = 'changelogSeenVersion'` persists dismissal
  per version; the close button, scrim, and Escape all mark it seen.
- The settings header badge is a `<button class="qp-head__badge qp-head__badge--action"
  aria-label="What's new in Quick Pricer">` holding the `info` icon; it removes the
  panel and opens the changelog, with explicit Enter/Space handling. Clear cache is
  text-only.
- Removed the unused `inventory_2` and `more_vert` icon map entries and their provenance
  assets in `docs/assets/material-icons/`.
- `tests/script.test.js`: 168 passing tests, including route gating of the bubble and
  changelog, Fill/clear rendering and labels, the drag hint, clear-all quantity and
  checkbox behavior, hashchange reset, the persisted changelog gate, and the settings
  info action.
