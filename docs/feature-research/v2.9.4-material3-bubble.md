## Existing Patterns to Reuse

- Keep API v2 batching and its v1 fallback untouched; only bubble progress rendering changes.
- Reuse existing modal accessibility helpers for the changelog dialog.
- Reuse existing position storage and viewport-clamping behavior under the new bubble class.
- Reuse the existing MutationObserver for route/DOM state refresh.
- Centralize icon path data in one map so the UI uses consistent Material 3 SVGs.
- Keep SVG assets in `docs/assets/material-icons/` for provenance while embedding paths in the single-file userscript.

## Findings

The v2.9.5 refactor is a UI and initialization layer change, not a pricing change. It can
be reintroduced without altering the verified API v2 queue. The current source already
has the key PDA initialization stages and the v2.9.5 no-focus behavior, so the port
must verify rather than duplicate them.

Material 3 assets should be downloaded once, reviewed, and mapped by semantic action.
The userscript should not depend on a runtime icon font or external SVG request because
it is distributed as a single userscript and must continue to work on PDA.

## Implementation Plan

1. Download and map the required Material SVG assets, centralize their path data, and

2. Port the circular bubble, route state, completion state, gesture handling, and
   changelog modal without changing pricing logic.
3. Bump all version metadata to 2.9.4 and update current documentation.
4. Add focused tests, run the full suite/lint, and perform a manual desktop/PDA smoke
   test.
