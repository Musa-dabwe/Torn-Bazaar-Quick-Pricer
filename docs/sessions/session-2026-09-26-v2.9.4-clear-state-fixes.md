# Session: 2026-09-26 v2.9.4 clear-state and overlay fixes
**Duration**: 2026-09-26 (subagent-driven development, Task 1 + Task 2)
**Project**: Torn-Bazaar-Quick-Pricer

## Objective
Three user-visible defects reported after the v2.9.4 bubble follow-up:

1. Switching the **Add Items** category left the bubble stuck in its post-fill
   `clear` state, offering to clear rows that were no longer loaded.
2. The clear action emptied only the quantity fields, leaving fetched prices visible
   and still applicable to a re-fill.
3. The settings header info action *replaced* the settings panel with the changelog,
   so reading the release notes discarded unsaved settings edits.

Tasks 1 and 2 of the plan (`docs/superpowers/plans/2026-09-26-v2.9.4-clear-state-fixes.md`)
covered (1)+(2) and (3) respectively; documentation and final verification closed both.

## Implementation Steps

### Task 1 — category reset and complete clear (`d4c4ecf`, `6e4983a`)
1. Extracted `clearRowInputs(itemElement, { onlyIfSet })` from `clearItemInputs()`;
   `clearItemInputs()` delegates to it, preserving its unconditional behavior.
2. Rewrote `clearAllQuantities()` to route every loaded row through that same clear, so
   the bulk path empties price **and** quantity, counts rows and fields, and reports
   `Cleared 2 items (4 fields)` / `Nothing to clear` in the toast. It still returns the
   row count for its callers.
3. Added `getVisibleAddCategorySignature()` (ordered leading loaded item IDs from the
   visible add rows) plus `isSameAddCategorySignature()` (exact match or prefix
   extension, so Torn's lazy-loaded rows do not count as a switch).
4. `updateBubbleState()` resets `bubbleMode` to `fill` on the Add route when that
   signature changes, and clears the cached signature on every other route.
5. Renamed `BUBBLE_LABELS.clear` to `Clear prices and quantities`, and corrected the
   comments/labels that still said "quantities", including the in-file 2.9.4 changelog
   note.
6. Hardened the item-ID lookup with an `img` fallback and added coverage for lazy-load
   growth, trailing-item collisions, shorter-category reloads, the observer debounce
   path, and the off-Add route.

### Task 2 — Settings stays open beneath the changelog

9. `torn-bazaar-quick-pricer.user.js:1024` — the settings info handler now calls

## Bugs Discovered & Fixed
- **Post-fill clear state survived a category switch** — Root cause: the `clear` mode
  was only reset by `hashchange`, and a Torn category tab click does not change the
  hash. Fix: signature comparison in `updateBubbleState()`. Status: **FIXED** (Task 1).
- **Clear left prices behind** — Root cause: `clearAllQuantities()` targeted quantity
  inputs only, duplicating less than the per-item clear already did. Fix: shared
  `clearRowInputs()`. Status: **FIXED** (Task 1).
- **Reading the changelog destroyed unsaved settings** — Root cause: the info handler
  called `overlay.remove()` before `showChangelog()`, and every dialog's Escape handler
  would have closed any overlay. Fix: stack the changelog and scope Escape to the
  top-most overlay. Status: **FIXED** (Task 2).
- **Stale documentation** — `docs/pastel-theme.md` and `CHANGELOG.md` still described
  a quantity-only clear and a settings-replacing info action. Status: **FIXED** (Task 2).

## Key Decisions Made
- **Escape is owned by the top-most overlay, not by whichever overlay the event
  happened to bubble through.** Overlays are siblings under `document.body`, so the
  event path already isolated them; the explicit `isTopOverlay()` check makes the
  invariant stated in code and testable, and prevents a future restructure from
  double-closing. It is deliberately narrow: a stacked dialog that somehow held focus
  while a dialog sat above it would ignore Escape, which is the correct trade.
- **The route-level gate was left exactly as it was.** It already refuses to open
  while any `.qp-overlay` exists, which is why the changelog cannot stack onto settings
  or the API prompt automatically. Only the settings info action stacks, and it calls
  `showChangelog()` directly. Widening the gate was out of scope.
- **No scroll lock, no `inert`/backdrop dimming change.** The changelog scrim already
  covers the page at the same `z-index`, so the panel beneath is not reachable by
  pointer while the changelog is up; adding `inert` would be a behavior change without
  a reported need.
- **In-file changelog note reworded** to "…opens the changelog above the panel, so
  closing it leaves your settings edits alone." The existing order tests still match it
  (prefix regex), and the note keeps its first-in-priority position.
